# Core schema and database checks (item 2)

Creates every table the pipeline writes to in `Listmanagement_core`, after checking
that the database and instance are ready. Nothing in the source databases
(`ListmanagementDB`, `Listmanagement_in`, `Listmanagement_filters`) is changed.

## What it does

1. **Database checks** (`sql/runner/preflight.py`)
   - **Compatibility level:** reads `compatibility_level` of the connected core
     database. If it is not 160, runs `ALTER DATABASE CURRENT SET COMPATIBILITY_LEVEL = 160`.
     It refuses to run if connected to a source database.
   - **Storage:** sums used pages in `Listmanagement_in` (catalog view, read only) and
     reads the latest `master.sys.server_resource_stats` sample. Stops if free instance
     storage (`reserved_storage_mb - storage_space_used_mb`) is less than **2x** the In data.
     `--skip-storage-check` bypasses this and logs a warning.
2. **Migrations** (`sql/runner/migrate.py`)
   - Creates `dbo.SchemaVersion` if missing.
   - Applies each `sql/migrations/V###__name.sql` in order, splitting on `GO` lines,
     in one transaction per script, and records it with a SHA-256 checksum.
   - Skips scripts already recorded. Stops with an error if an applied script was
     edited. Fix forward with a new `V###` script instead.

## Inputs

- `Vertical` / `VerticalField` (sample copies in `tests/sample_data/`): the source of
  the per-vertical attribute columns and types.
- The In table layout (e.g. `Listmanagement_in.dbo.MortgageInfo`): `ID`, `OfferID`, then
  the vertical's fields. `Text` → `varchar(MaxLength)`, `Number` → `decimal(14,3)`,
  `Date` → `datetime2(3)`.
- `config/fieldmaps/core_columns.txt`: fields stored in the shared tables and so not
  repeated per vertical.
- `config/fieldmaps/insurance_excluded_health.txt`: Insurance health fields kept out of
  the core. `Uninsurable`, `HeightFeet`, `HeightInches`, `Weight`, `Smoker`, `HealthConditions` and `RecentConcern`
  are kept. All other health fields are excluded.

## Outputs (tables in `Listmanagement_core.dbo`)

| Table | One row per | Notes |
|---|---|---|
| `PipelineRun` | step run | `RunID` is written by every other table |
| `Person` | person | unique `(PhoneStd, LastNameStd)`, `FirstSeenAt` |
| `LeadEvent` | opt-in (In row) | `PersonID`, `VerticalID`, `OfferID`, `SourceInID`, `LeadID`, `TrustedToken`, `OptInTimeStamp`, `DuplicateOfEventID`; unique `(VerticalID, SourceInID)` |
| `Contact` | event | names, phones, email: `*Raw` next to `*Std` |
| `Address` | event | address, city, state, zip, county: `*Raw` next to `*Std` |
| `MortgageAttr`, `InsuranceAttr`, `SolarAttr`, `StudentAttr`, `HomeOwnerAttr` | event + `ValueSource` | typed vertical fields; `ValueSource` is `lead` or `enriched` (for 1B) |
| `QualityFlag` | problem found | unique `(LeadEventID, FlagCode, FieldName)` |
| `DNC` | blocked value | `DNCType` phone / email / address, `Value`, `Reason`, `DateAdded` |
| `RecordStatus` | event | `active` / `duplicate` / `blocked`; non-active needs a `Reason` |
| `DuplicateReport` | duplicate found | `DuplicateOfEventID`, `MatchRule`, per run |
| `FieldMap` | source column | target core column, or `Included = 0` with a reason |
| `Watermark` | source table + step | last source ID read |
| `OfferType` | offer | e.g. `co-reg`; side table so `ListmanagementDB.Offer` is never altered |
| `SchemaVersion` | applied script | created by the runner, not by V001 |

`OfferID` and `VerticalID` refer to `ListmanagementDB`. SQL Server has no
cross-database foreign keys, so these links are logical only.

The `*Attr` section of V001 is generated by `tools/gen_attr_ddl.py` and pasted in once.
If VerticalField changes, add new columns in a new `V###` script. Don't edit V001.

## How to run

One-time, by a DBA with an admin login: run `sql/admin/grant_dataengine_pipeline.sql`.
It grants `VIEW SERVER STATE`, plus `db_ddladmin`, read/write and `ALTER` on
`Listmanagement_core` only. Section 3 sets up the dev test database.

On the Windows VM:

```powershell
pip install -r requirements.txt
# store the password once in Windows Credential Manager:
python -c "import keyring, getpass; keyring.set_password('dataengine', 'dataengine_pipeline', getpass.getpass())"

$env:DATAENGINE_SQL_SERVER = "<managed instance host>"
python -m sql.runner.migrate --dry-run   # list pending scripts, change nothing
python -m sql.runner.migrate
```

To use Azure Key Vault instead, set `DATAENGINE_KEYVAULT_URL` (and optionally
`DATAENGINE_KEYVAULT_SECRET`, default `dataengine-pipeline-sql`).

## Re-run behaviour

- A second run applies nothing, records nothing and changes no objects.
- Every statement in V001 is guarded (`IF OBJECT_ID(...) IS NULL`, `IF NOT EXISTS` on
  indexes), so even running the script by hand twice is safe.
- A failed script is rolled back and not recorded, so the next run retries it.

## Tests

```bash
pip install -r requirements-dev.txt
pytest                                  # static + unit tests, no database
```

Live test against the dev Managed Instance (uses the empty `Listmanagement_core_test`):

```bash
DATAENGINE_SQL_DATABASE=Listmanagement_core_test pytest tests/sql/test_migration_integration.py
```
